## 0. set_memory

Replace this server's (or client's) memory with new content; the old memory is discarded. Memory is shown to the model with every event, is shared by all of the instance's connections and outlives each one, unlike the history of a single connection, which ends with it. Keep here anything needed later by every connection: data you stored, counters, settings.

Parameters:
- `value` (string, required): New memory value as a string. Replaces all existing memory.

Example:
```json
{"type":"set_memory","value":"users_created: alice,bob\nnext_order_id: 1043"}
```

## 1. append_memory

Add lines to this server's (or client's) memory; existing memory is kept. A line written `key: value` replaces an earlier line with the same key instead of adding a second one. Memory is shown to the model with every event, is shared by all of the instance's connections and outlives each one.

Parameters:
- `value` (string, required): Text to append as a string, one fact per line. A `key: value` line replaces the earlier line with that key; any other line is added after the existing memory.

Example:
```json
{"type":"append_memory","value":"connection_count: 5\nfiles_uploaded: 3"}
```

## 2. set_connection_memory

Replace the notes kept about the peer on THIS connection: their name, what they chose, whether they logged in. Shown with every later event on this connection only — never to any other connection — and discarded when it closes. Use this, not set_memory, for anything about one peer.

Parameters:
- `value` (string, required): The connection's new notes; replaces all of them.

Example:
```json
{"type":"set_connection_memory","value":"user_name: alice\nlogged_in: yes"}
```

## 3. append_connection_memory

Add lines to the notes kept about the peer on THIS connection (their name, choices, login state). A `key: value` line replaces an earlier line with the same key. Shown with every later event on this connection only, never to another connection, and discarded when it closes. Use this, not append_memory, for anything about one peer.

Parameters:
- `value` (string, required): Lines to add, one fact per line; `key: value` replaces that key.

Example:
```json
{"type":"append_connection_memory","value":"user_name: alice"}
```

## 4. append_to_log

If you are asked to log information for the user, use this to append logs to a file. Use this to create access logs, audit trails, or any persistent logging.

Parameters:
- `output_name` (string, required): Name of the log output (e.g., 'access_logs'). Used to construct the log filename netget_<name>_<time>.log, so it may contain only A-Z, a-z, 0-9, '_' and '-' (1-64 characters); anything else is refused.
- `content` (string, required): Content to append to the log file.

Example:
```json
{"type":"append_to_log","output_name":"access_logs","content":"127.0.0.1 - - [29/Oct/2025:12:34:56 +0000] \"GET /index.html HTTP/1.1\" 200 1234"}
```

## 5. accept_bolt_login

Let this login in. NetGet answers the client's LOGON with SUCCESS and the connection can run queries.


Example:
```json

```

## 6. reject_bolt_login

Refuse this login. The client receives a FAILURE with the code (default Neo.ClientError.Security.Unauthorized) and the connection closes.

Parameters:
- `code` (string): A Neo.ClientError.Security.* status, e.g. Neo.ClientError.Security.Unauthorized or Neo.ClientError.Security.AuthenticationRateLimit
- `message` (string): The message the client prints

Example:
```json
{"type":"reject_bolt_login","code":"Neo.ClientError.Security.Unauthorized","message":"The client is unauthorized due to authentication failure."}
```

## 7. close_connection

Close the Bolt connection without answering


Example:
```json
{"type":"close_connection"}
```


## Understanding Memory

Memory is ONE string shared by every connection of this instance and kept after they close. Use it for instance-wide facts: counters, resources you created, settings, what you promised a peer you would remember.

**Key Points:**
- Memory is a **string** (not JSON). Use newlines to separate values, one fact per line
- `set_memory` - Replace all memory (use for major state changes)
- `append_memory` - Add lines to existing memory. A line written `key: value` replaces the earlier line with that key, so update a fact by appending it again
- What happened earlier on *this* connection is shown separately, above the event, when the instance keeps history; it is bounded and ends with the connection.
- **Facts about the peer on this connection** (their name, what they chose, whether they logged in) go in `set_connection_memory` / `append_connection_memory`, never in shared memory: every other peer's events read shared memory. Connection memory is shown above this connection's events only and ends when it closes

**Example:** `"login_count: 4\nfiles: a.txt,b.txt"`

Never put credentials in memory: it is repeated into every later prompt.
