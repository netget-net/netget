# Selected Nostr client

Experimental NIP-01 client beside the existing programmable relay. Native WS and WSS use one WebSocket connection; WSS verifies the host certificate with Rustls and WebPKI roots. Browser transport supports WS. A path is allowed; URL credentials, query and fragment are refused. Default connect/write/publish-OK/NIP-11 deadline is15 seconds, configurable1..30. There is no idle subscription deadline or automatic reconnect/replay.

The model chooses public event content and filters. NetGet signs with one startup secret_key, or a fresh generated identity, using the existing pure RelayKey SHA256/BIP-340 implementation. The key never enters actions, events, status, diagnostic text or the handler prompt; owned task contexts discard their private startup parameter copy. nostr_connected includes only the public signing identity. No key file/helper, arbitrary private-key action, supplied id/signature or raw WebSocket action is offered.

| Action | Wire and result |
|---|---|
| nostr_publish | EVENT with unmodified UTF8 content, native kind/timestamp/tags, computed id and signature. Later nostr_publish_result correlates OK by event id. accepted preserves the native boolean and reason_prefix preserves extension prefixes. A timeout has accepted=null and does not prove rejection. |
| nostr_subscribe | REQ with a nonempty subscription_id and1..10 filters. Reusing an id replaces its filters. OR between filters, AND within a filter; ids/authors/#e/#p require full lowercase hex, kinds0..65535, since/until inclusive, limit0..500, #single-letter tag lists. Lists are nonempty and at most500 values. Unknown filter extensions refuse. |
| nostr_close | CLOSE and immediate local subscription removal. local_close does not claim relay acknowledgement; NIP-01 has none. Already-selected EVENT/EOSE/CLOSED frames for locally absent ids are ignored. |
| nostr_relay_info | GET at the same URL converted to HTTP(S), Accept application/nostr+json. Selected optional NIP-11 fields and typed limitations; unknown fields ignored, absent/null optional fields omitted. Advertised limits/NIPs are informational, never fabricated or claimed as negotiated enforcement. |
| disconnect | Cancel owned pending I/O and close the connection. |

nostr_received_event exposes the complete public event only after native schema, content hash and signature verification. stored_phase records whether EOSE has been observed on the current local subscription. EOSE remains live; limit0 requests no stored events while allowing later updates. Filter replacement and incoming frames have no wire generation identifier: a frame already selected under old filters can arrive after replacement, so matches_current_filters is informational and a mismatch alone is not a protocol failure. An already-selected EOSE can likewise precede the replacement's own EOSE. No deduplication/archive or local replaceable/ephemeral/expiration policy is introduced.

nostr_subscription carries eose, native closed reason/prefix, or local_close. Uncorrelated/late OK messages are ignored after bounded publication state has expired or completed. NOTICE remains native bounded text. AUTH/COUNT/unknown extensions produce an explicit unsupported notice; challenges/count bodies are omitted and never trigger signing or raw requests. No NIP-42/NIP-45 actions are offered; the existing relay's explicit refusal remains unchanged.

Selected NIP-11 fields: name, description, contact, banner, icon, software, version, terms_of_service; pubkey is the administrative contact and self the relay identity, both validated as32-byte lowercase hex; supported_nips is an optional integer list. Selected limitation fields retain native nonnegative integers/booleans, including authentication/payment/restricted-write declarations and zero limits. No fee/admission policy, automatic authentication or payment.

Bounds:128KiB messages/frames/NIP-11 bodies,64KiB content,2000 tags of1..32 strings (4096 bytes each),4096-byte notices/reasons/tag filter strings,64 Unicode characters per subscription id,20 current subscriptions,16 pending publication ids, one NIP-11 request. All constructed values preflight iteratively at depth8/nodes25000/retained2MiB before copies/serialization; rejected owned values drop iteratively. Wire JSON uses serde's parse depth bound and the same smaller content budget. Oversized outgoing encoded frames refuse before I/O. Body compression, redirects/proxies/custom trust/client certificates refuse or are absent.

Two registered owned tasks: session and event dispatcher. The command channel exists before connected/manual dispatch. Queues8 and four handler followups bound retention/work; queue overflow ends the session explicitly. Relay reads/pings continue during manual/model handling and a pending owned NIP-11 future. Pending writes have whole deadlines and service queued disconnects; other commands refuse while writing. Removal aborts both tasks and owned socket/HTTP futures. Local shape/cap errors refuse without wire side effects; malformed/binary/invalidly-signed relay data fails the session with fixed diagnostics. Shared AppState memory and ordinary event rules remain the only generic memory mechanism.

Independent required peers: nak0.20.7 (fiatjaf.com/nostr and coder/websocket; no shared framing or crypto) as an owned in-memory relay and CLI producer/consumer/verifier; rust-nostr0.45.1 through Python nostr_sdk fetches and verifies the client's public event. Existing relay-server tests retain independent nak/SDK and Wireshark evidence. Client tests include real static/script/model/injection paths, shared memory, a NetGet pair, native auth-required refusal and cancellation. No skip-if-missing peers. Experimental does not claim complete Nostr/NIP coverage, positive WSS/browser runtime evidence or client capture/conformance.

Primary specifications: [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md), [NIP-11](https://github.com/nostr-protocol/nips/blob/master/11.md), [pinned nak serve source](https://github.com/fiatjaf/nak/blob/v0.20.7/serve.go). Verification is under tests/client/nostr; run the programme Cargo guard.

Batching is On: relay messages raised while the model answers wait in the dispatcher queue (8), and with batching on the dispatcher drains everything waiting into one call_llm_for_client_batch call, one event each; off, one event per call. Each received event carries its own id and subscription, and a batch's follow-ups are as deep as its deepest event, so the four-followup bound holds. Draining also empties sooner the queue whose overflow ends the session. tests/client/nostr/batching_test.rs is the off/on pair.
